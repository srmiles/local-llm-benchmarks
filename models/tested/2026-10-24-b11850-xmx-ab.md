## The PR

[ggml-org/llama.cpp#29864](https://github.com/ggml-org/llama.cpp/pull/29864) "Multi-column on Intel XMX matrix engines refactored", merged 2026-10-22, written and measured on an **Arc Pro B70**. It adds int8-DPAS (ESIMD) `mul_mat_vec_q` kernels for **2–80 activation columns** on *reordered* weights — the shape of speculative-decode verification (n-max + 1 columns) and short prompt batches. The existing dp4a multi-column kernels redo weight unpack and scale arithmetic per column, so their cost grows with the batch; on a B70 the PR author measured a 4-token step at 46% above a 1-token step before the change.

What gates it, read from the merged source (`ggml/src/ggml-sycl/common.hpp`):

| Gate | Value | Where |
|---|---|---|
| Compiled in | whenever `<sycl/ext/intel/esimd/xmx/dpas.hpp>` exists — no build flag | `common.hpp:237-239` |
| Runtime switch | `GGML_SYCL_ENABLE_XMX_ESIMD`, default **1** (the PR text says `GGML_SYCL_ENABLE_XMX`; the code does not) | `ggml-sycl.cpp:444` |
| Arch | `bmg_g21`, `bmg_g31`, `lnl_m` — **B60 is `bmg_g21`, so it is on by default here** | `common.hpp` `ggml_sycl_xmx_supports_arch` |
| Weight types | **Q2_K, Q3_K, Q4_K, Q5_K, Q6_K, Q8_0** — not Q4_0, not any IQ type, not NVFP4 | `common.hpp:247` `ggml_sycl_xmx_supports_type` |
| Columns | 1–80 (`GGML_SYCL_XMX_MAX_COLS`); 1 column only for Q2_K/Q3_K/Q4_K | `common.hpp:242`, `:268` |

That type list is the whole story of the result below.

## Build

Upstream `9ae73e68f` (reports **b11850**, 2026-10-24) + the local `ggml-sycl` series rebased as branch `bmg-tilekv-9ae73e68f` → image **`llama.cpp:sycl-f16-9ae73e68f-patched-3bd0de68e`**, 12 min with layer cache.

The series went on with **two conflicts, both resolved by dropping a patch** rather than hand-merging:

| Dropped | Why it was safe |
|---|---|
| `749b075e9` chunk MMVQ above `MMVQ_MAX_BATCH_SIZE` (0005) | #29864 rewrote the same `can_use_mul_mat_vec_q` gate. The patch is **inert unless `GGML_SYCL_MMVQ_MAX_COLS` > 8**, and both production launchers pin it to 8 (`docker inspect` on `:8002` / `:8011`). |
| `b7d8ce69b` let the reorder survive a concurrent batch | Depends on 0005's `mmvq_max_cols()` helper and is equally inert at 8. |

Six patches applied cleanly. A seventh was added the same day for the Bolt 74B DFlash crash — see [Nemotron 3.5 Bolt](nemotron-3.5-bolt.md) and [`0006`](../../configs/patches/0006-sycl-report-OUT_PROD-unsupported-for-non-contiguous.patch); it is committed on the host branch but **not in this image**.

## Method

Card 2 (`level_zero:1`, `0000:0b:00.0`) via `bench-slot.sh` on `:8020`; `:8011` stopped for the window. `bench-candidate.py`: 20 decode runs × 300 tokens at temp 0.6 / top-p 0.95 / top-k 20, prefill at 500 / 2K / 5K / 12K. Three arms interleaved model by model, three rounds:

| Arm | Image | Env |
|---|---|---|
| `old` | `sycl-f16-9d1878a43-patched-def76ec9a` (current production) | — |
| `new` | `sycl-f16-9ae73e68f-patched-3bd0de68e` | `GGML_SYCL_ENABLE_XMX_ESIMD=1` (default) |
| `noxmx` | same as `new` | `GGML_SYCL_ENABLE_XMX_ESIMD=0` |

`noxmx` is the control that matters: it holds every other upstream commit between `9d1878a43` and `9ae73e68f` constant and removes only the PR.

Production launcher settings for both models: Ornith Q4_K_M + Q8_0 MTP head, `--spec-draft-n-max 3`; Nemotron Q4_0 + Q8_0 MTP head, `--spec-draft-n-max 7 --spec-draft-p-min 0.6`.

Reading it:

- **Ornith: `new` beats `old` in every round, and `noxmx` ≈ `old` in every round.** The ~130 other upstream commits in the bump are worth nothing measurable here; the PR is worth all of it.
- **Acceptance is unchanged (75.5 → 76.1%)**, so the gain is the per-step cost of verifying 4 columns on Q4_K weights — exactly the case the PR targets — not more accepted tokens.
- **Quote the pooled mean, not the median.** Ornith decode is bimodal run to run (finding #31); round 3's medians were 103.5 vs 91.2 (+13%), round 1's 121.2 vs 78.7 (+54%). Finding #53's rule (b) applies.
- **Nemotron is flat because the PR does not cover it.** Its target weights are Q4_0, which is not in `ggml_sycl_xmx_supports_type`; only the Q8_0 MTP head qualifies, and the head is a small slice of each step.
- **Ornith peak VRAM +0.7 GiB in round 1 only** (12.08; rounds 2–3 at 11.31). Treated as noise until it repeats.

**Caveat on round 1, Ornith only:** CPU work (embed GGUF conversions, then a CPU reference-embedding job) overlapped the `old` and the start of the `new` Ornith arms by mistake; it was killed as soon as it was noticed. Rounds 2 and 3 are clean and give the same verdict; the pooled numbers above include round 1 and the conclusion does not depend on it.

## What to do with it

1. **Cut `:8002` (Ornith) to `sycl-f16-9ae73e68f-patched-3bd0de68e`.** Not done in this session.
2. `:8011` (Nemotron) gains nothing from this image. Moving it is about staying current, not speed.
3. **The real follow-up is quant choice.** Any production slot on Q4_0 is now leaving this kernel unused. Nemotron Q4_K_M does not fit the card (finding #26), but the Gemma 4 E2B categorise slot (QAT Q4_0) and the Gemma 4 26B fallback (QAT Q4_0) are both worth re-measuring against a K-quant on this build — finding #2's QAT-vs-K-quant ordering has flipped on builds before, and this PR is a new reason it could flip again.
