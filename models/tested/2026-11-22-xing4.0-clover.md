# Xing4.0-29B-A4B and Clover-35B-A3B-Preview — Tested 2026-11-22

**Status: neither displaces Nemotron 3.5 Lightning on `:8011`.**
- **Clover:** fully on GPU (2 splits). Decode 70.3 tok/s undrafted, about 5 % below undrafted Nemotron on the same binary, and prefill about 25 % lower. It has no MTP head, so Nemotron + MTP (about 92 at n-max 7) stays well ahead. Quality is untested (finding #71).
- **Xing:** decode about 24 tok/s, and prefill falls to 138 tok/s at 12K. **Card 2 had a CCS engine reset** during its decode runs, so the window was stopped (finding #70).

Raw results, runners, kernel lines and the coredump: [`configs/benchmarks/20261122-xing-clover/`](../../configs/benchmarks/20261122-xing-clover/).

## Method

- Image: `llama.cpp:sycl-f16-unsloth-b12588-c0c3de8` (server) and `-full` (`llama-bench`). This is the same unpatched build as the [Inkling bench](2026-11-22-inkling-2-mini.md). It is **not** the production patched series.
- Card 2, `:8020`, via [`bench-slot.sh`](../../configs/launchers/bench-slot.sh): `-c 131072`, q8_0 KV, `-fa on`, `--reasoning off`. `:8011` was stopped for each window, with `card2-empty.sh` before every launch.
- `bench-candidate.py`: prefill 3 × {500, 2K, 5K, 12K}; decode 20 × 300 tokens at temp 0.6 / top-p 0.95 / top-k 20.
- `llama-bench -ngl 99 -fa 1 -ctk q8_0 -ctv q8_0 -ub 2048 -b 2048 -p 512,4096 -n 128 -r 3`. The Nemotron control row comes from the Inkling window earlier the same day, on the same `-full` image.
- The Clover window added two guards after the Xing reset ([`clover.sh`](../../configs/benchmarks/20261122-xing-clover/clover.sh)):
  - a split check before the harness (finding #69)
  - a watcher that stops the window on a new `engine_class=ccs` line in dmesg, or on `n_decode_total` frozen for 60 s with a request in flight (finding #66 rule b)

### Xing: why it is slow (not confirmed)

Prefill *drops* as the prompt gets longer (456 → 138 tok/s from 2K to 12K). On Inkling, the same shape came from attention running on the CPU (finding #69). Xing uses MLA attention, and its llama.cpp PR changed no ggml-sycl files. **The split count was not measured** before the window was stopped, so this is a hypothesis.

The embedded nextn layer (`blk.40.nextn.*`) loads as "unused" without `--spec-type draft-mtp`. The MTP arm was never reached.
